панели управления и 33 пункта «Инструментов Windows». Здесь: принципы, таблица решений по каждому пункту,

### 1. Принципы

1. **Своё лицо, не копия.** Логика Windows узнаваема (человек находит нужное), названия и группировка наши.
   Реестра нет: вместо него текстовые файлы в `/etc` и редактор конфигурации с описаниями ключей.
2. **Два уровня, без дублей.** «Параметры» = современные страницы для обычных настроек (одна настройка живёт
   в ОДНОМ месте). «Панель управления» (`/bin/ctlpanel`, ярлык «Все элементы») = центр для опытных:
   сетка значков-инструментов; каждый значок либо запускает инструмент, либо открывает страницу «Параметров»
   (`Settings::open(Section)` — уже есть для трея). Ни одна настройка не реализуется дважды.
3. **Группировка вместо длинной сетки.** Не 60 значков подряд, а 6 групп: Система и железо, Сеть и связь,
   Люди и доступ, Программы и игры, Данные и диски, Журналы и обслуживание. Каждая группа — строка со
   сворачиванием. Вверху поиск по всем настройкам и инструментам (расширить поиск «Параметров» `ALL`).
4. **Достижимость.** Каждый инструмент: (а) папка «Пуска» «Системные утилиты» или «Средства
   администрирования»; (б) поиск «Пуска»; (в) «Выполнить» (Win+R: короткое имя `taskmgr`, `services`,
   `eventlog`); (г) для терминала — одноимённая команда.
5. **Незавершённое не прячем:** пункт с пометкой «функция запланирована» (правило вехи v0.7b).
6. **Каждый инструмент — отдельная программа на `mini-ui::kit`** (как taskmgr/devmgr), окно по
   2/3 экрана, без нового кода в ядре, если хватает существующих вызовов. Ядро добавляет только узкие
   «читающие» вызовы (журнал, службы, таймеры).
7. **Административное — через права.** Изменяющие действия спрашивают подтверждение и проверяют учётку
   (`perms`); обычный пользователь видит инструмент только для чтения.
8. **Проверка в QEMU.** Каждая программа получает шаг в сценарии стенда (`xtask/src/harness/scenarios.rs`):
   запуск из «Пуска» → снимок → одно действие → строка в журнале.

### 4. Порядок фаз и проверки

**Фаза П1 (дёшево, высокий эффект)**
1. Папки «Пуска»: «Системные утилиты» (Блокнот, Калькулятор, Терминал, Выполнить, Таблица символов,
   Диспетчер задач, Монитор системы) и «Средства администрирования» (пока пусто/ссылки на настройки).
   Проверка: сценарий `desktop` открывает «Пуск» → папка → Калькулятор; снимок; поиск «блокнот» находит.
2. «Выполнить» (Win+R). Проверка: набрать `calc` → окно калькулятора; `settings:network` → страница сети.
3. «Таблица символов». Проверка: выбрать «Ж», «Копировать» → вставить в блокнот (проверка по строке).
4. Мышь (скорость, левша, двойной щелчок) и «Доступность» (масштаб, контраст) — страницы «Параметров».
   Проверка: сценарий `settings`: сохранить → строка `mouse speed saved`.
5. «Сведения о системе» (дерево + экспорт в файл). Проверка: файл создан, содержит версию и PCI.

**Фаза П2 (инструменты диагностики — главная ценность для нас)**
6. «Журнал событий» (ядро + `LOG.TXT`) с фильтром и «Сохранить для разбора».
   Проверка: сценарий `crash` (падение программы) → событие в журнале; фильтр «ошибки» оставляет его.
7. «Службы» (окно) над init: запуск/стоп. Проверка: `svcbad` падает → видна «упала», кнопка «Перезапустить».
8. «Монитор ресурсов» (расширение `sysmon`: по процессам, диск, сеть).
9. «Очистка диска». Проверка: создать фиктивный кэш в `/tmp`, очистить, размер уменьшился.
10. «Конфигурация загрузки» и «Автозагрузка». Проверка: добавить автозапуск → после перезапуска сценария окно открыто.

**Фаза П3 (хаб и сложное)**
11. «Панель управления» (`ctlpanel`): группы, поиск, значки на инструменты и страницы «Параметров».
    Проверка: открыть, ввести «звук» в поиск → единственная плитка → Enter открывает страницу.
12. «Управление компьютером» (оболочка с деревом).
13. «Редактор конфигурации», «Шрифты», «Региональные стандарты», «Состояние системы» на Home.
14. «Драйверы и видеокарта» + «Игры и Proton/Wine» (на ПК Романа вместе с проверкой образа).
15. «Менеджер пакетов» (окно).

**Фаза П4 (позже, по спросу)**
Планировщик, резервные копии, обслуживание дисков, шифрование тома, сетевой фильтр, связка ключей,
индексация, мастер неполадок, проверка памяти (окно), запись шагов, «Удалённый доступ», аварийная флешка.

### Решения, которых ждём от Романа
- Название хаба: «Панель управления» (как у Windows) или своё; предложение — «Пульт» с подписью «Панель управления».
- Должен ли «Журнал событий» писать на флешку непрерывно (`LOG.TXT` уже есть) или только по кнопке.
- Порядок: сначала П1 (папки + «Выполнить») или сразу журнал (П2).
