# Договор ядра с программой

Этот документ — для того, кто пишет программу под FreeOS или собирает под неё
чужую. Источник правды — крейт [`crates/user-abi`](../crates/user-abi/src/lib.rs):
таблицы ниже собраны из его констант и первой фразы их документации. Если
документ и крейт разошлись, прав крейт, а документ устарел.

## Версия и правило изменения

Текущая версия — **`0x0001_0004`** (`user_abi::ABI_VERSION`).

- **Номер вызова, однажды выданный, не переиспользуется.** Новый вызов получает
  следующий свободный номер; отменённый остаётся занятым навсегда и отвечает
  `ERR_NO_SYSCALL`.
- **Поля в середину структур не вставляются.** Новое поле дописывается в конец,
  и только если структура при этом растёт — что тоже изменение версии.
- **Младшая половина версии растёт**, когда вызовы добавляются: программа,
  собранная раньше, продолжает работать — всё, что она знала, осталось на месте.
- **Старшая** — когда что-нибудь меняет смысл. Такого не случалось и случаться
  не должно.

Правило держится не обещанием, а тестами крейта: они называют каждый номер,
каждый код и размер каждой структуры числом. Тест, который пришлось поправить,
— это и есть разговор о смене версии, который иначе не состоялся бы.

«Заморозить» договор насовсем сейчас нельзя: система ещё растёт. Поэтому он
версионирован, а не заморожен.

### История

| версия | что добавилось | коммит |
|---|---|---|
| `0x0001_0000` | договор перестал меняться: вызовы, которых требует libc (фаза 44) | `05967d2` |
| `0x0001_0001` | страница процесса `PROCESS_PAGE` с эталоном канарейки стека | `fb34dc3` |
| `0x0001_0002` | потоки: `SYS_THREAD_CREATE`, `SYS_SET_TLS`, `SYS_THREAD_EXIT` | `19bdc9c` |
| `0x0001_0003` | ожидание на адресе: `SYS_FUTEX_WAIT`, `SYS_FUTEX_WAKE` | `d5d9e9e` |
| `0x0001_0004` | драйверы-программы: `SYS_DEVICE_OPEN`, `SYS_DEVICE_MAP`, `SYS_DEVICE_WAIT`, `SYS_DMA_ALLOC` | (Д1) |

## Соглашение о вызове

Взято у Linux — не из уважения к традиции, а потому что оно уже описано и
знакомо:

```text
  x86-64    номер в rax, аргументы в rdi, rsi, rdx; результат в rax; int 0x80
  aarch64   номер в  x8, аргументы в  x0,  x1,  x2; результат в  x0; svc #0
```

Аргументов не больше трёх; то, что в три не помещается, передаётся структурой
по указателю (`Launch`, `WindowSpec`). Результат неотрицателен при успехе и
отрицателен при отказе — это код ошибки из таблицы ниже.

Дескрипторы 0, 1 и 2 — стандартные ввод, вывод и поток ошибок; первый
свободный — 3; одновременно открытых файлов у программы не больше восьми
(`MAX_OPEN_FILES`).

По адресу `PROCESS_PAGE` (`0x0000_0080_60c0_0000`) ядро отображает каждой
программе страницу только для чтения; первые 16 байт в ней случайны, и из них
берётся эталон канарейки стека. Программы на Rust и на C, собранные набором
из `cargo xtask sdk`, пользуются ею сами.

## Какой файл ядро запускает

ELF64 для своей машины, без динамического загрузчика (`PT_INTERP` отвергается).
Два вида:

- **`ET_DYN`, статическая PIE** — так с 26.09.2026 собирается всё своё. Ядро
  кладёт образ на случайную страницу гигабайтного окна с `0x0000_0080_0000_0000`
  (ASLR) и входит по `e_entry` плюс этот сдвиг. **Перемещения ядро не
  применяет** — это дело стартового кода программы (`libc/freeos/start-<арх>.s`,
  в `crt0.o` набора и в `user_progs`): поддерживается ровно `R_*_RELATIVE`.
- **`ET_EXEC`** по своему адресу внутри того же окна — так было собрано всё до
  26.09, и такие программы по-прежнему запускаются, только без сдвига.

Вход: `argc` и `argv` в первых двух регистрах соглашения (`rdi`/`rsi`,
`x0`/`x1`), стек выровнен на 16. Стек и начало памяти по запросу у каждого
запуска тоже свои.

## Коды ошибок

| код | имя | что значит |
|---|---|---|
| -2 | `ERR_NO_SYSCALL` | Ошибка системного вызова: номера нет. |
| -3 | `ERR_BAD_ADDRESS` | Ошибка системного вызова: аргумент указывает за пределы памяти программы. |
| -4 | `ERR_NOT_FOUND` | Такого файла или каталога нет. |
| -5 | `ERR_PERMISSION` | Права не позволяют. |
| -6 | `ERR_BAD_FD` | Дескриптора с таким номером у программы нет. |
| -7 | `ERR_TOO_MANY_FILES` | Открыто уже `MAX_OPEN_FILES` файлов. |
| -8 | `ERR_IO` | Носитель отказал или структура на нём испорчена. |
| -9 | `ERR_UNSUPPORTED` | Операция файловой системе не по силам: запись в том, смонтированный на чтение, открытие каталога как файла. |
| -10 | `ERR_NO_FILESYSTEM` | Файловая система не смонтирована — спрашивать не у кого. |
| -11 | `ERR_BAD_PATH` | Путь синтаксически негоден: не абсолютный, пустой компонент, не UTF-8. |
| -12 | `ERR_NO_PROGRAM` | Ядро не нашло программы, от имени которой пришёл вызов. |
| -14 | `ERR_EXISTS` | Такое имя уже занято. |
| -15 | `ERR_NOT_EMPTY` | Каталог не пуст. |
| -16 | `ERR_NO_SPACE` | На носителе кончилось место. |

| -18 | `ERR_NO_TASK` | Задачи с таким номером нет — или уже нет. |
| -19 | `ERR_TOO_MANY_TASKS` | В таблице задач нет места под ещё одну. |
| -20 | `ERR_NO_NETWORK` | Сети в системе нет: карту не нашли или адрес не задан. |

## Коды завершения, которые ставит ядро

Программа, снятая ядром, не выбирает свой код сама — его ставит ядро, и эти
два числа нельзя спутать с кодом, который программа вернула бы добровольно.

| код | имя | когда |
|---|---|---|
| -1 | `EXIT_FAULTED` | Код возврата, которым ядро завершает программу, снятую из-за отказа. |
| -13 | `EXIT_KILLED` | Код возврата, которым ядро завершает программу, снятую по требованию. |
